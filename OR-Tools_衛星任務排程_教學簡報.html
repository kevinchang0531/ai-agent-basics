02 / Why scheduling is hard

排程難，是因為資源不足與限制會互相撞在一起。

INPUT 01任務需求目標、優先級、持續時間、截止時間
INPUT 02可見窗口衛星能看見目標的時間區段
INPUT 03有限資源姿態、能源、記憶體、天線、下傳鏈路
RULES不能衝突同一時間不能做兩件互斥的事
GOAL取捨在可執行前提下最大化任務價值
指揮官視角：「今天拍最多張」不一定是好答案；好答案是能在能源、姿態、下傳與時限都合規時，完成最有價值的任務。

Google 將 scheduling 定義為：在特定時間把資源分配給任務；CP 適合處理大量異質限制條件。官方說明

03 / What is OR-Tools?

OR-Tools 是一個「最佳化工具箱」

OR = Operations Research

把有限資源分配到許多可能方案中，尋找最佳或足夠好的決策。

SchedulingRoutingPackingAssignment

Python 只是建模語言

您用 Python 描述問題；真正搜尋解答的是 CP-SAT、MIP、流量或路由等求解器。

Model→Solver→Solution

CP-SAT

適合布林決策、時間區間、互斥與複雜規則，是本課主角。

MIP

MIP（Mixed-Integer Programming，混合整數規劃）適合線性與混合整數模型；連續量與成本模型常見。

Solver 控制

可設定時間上限，取得最佳解、可行解或在時限內最好的解。

04 / The mental model

把一個排程問題拆成三層

A

決策變數

電腦要替我們決定什麼？例如：任務是否執行、何時開始、分配哪些資源。

衛星例子：觀測 A 是否選取？開始時間是多少？
B

限制條件

什麼事情不可以發生？例如：時間窗外不可執行、同一資源不可重疊。

衛星例子：姿態機動完成前不能拍攝。
C

目標函數

在所有可行答案中，想讓什麼最大或最小？

衛星例子：最大化任務價值，或最小化延遲與燃料成本。

先求「做得到」，再談「哪一個最好」。

05 / Satellite case

從三個觀測任務開始：哪一組能排進去？

任務可執行窗口持續價值
災害區 A01:00–03:0030 分100
海岸線 B02:00–05:0045 分70
雲量監測 C04:00–06:0030 分45

假設：三個任務共享同一個觀測酬載；同一時間只能執行一個任務。

限制 1：任務只能在自己的可見窗口內執行。
限制 2：同一酬載的任務不可重疊。
限制 3：任務可選做，不必全部接受。
目標：最大化總任務價值。
指揮判讀

人眼可以處理三個任務；當任務、衛星、資源、窗口增多後，人工容易漏掉衝突，模型則能把規則固定下來反覆重算。

06 / Python model

程式的核心不是「寫很多行」，而是把規則寫對。

概念版：每個任務是一個可選的時間區間

from ortools.sat.python import cp_model

model = cp_model.CpModel()
horizon = 360
intervals = []
selected = {}

for name, window, duration, score in tasks:
    start = model.new_int_var(
        window[0], window[1] - duration, name + "_start")
    end = model.new_int_var(0, horizon, name + "_end")
    use = model.new_bool_var(name + "_selected")
    interval = model.new_optional_interval_var(
        start, duration, end, use, name)
    intervals.append(interval)
    selected[name] = use

model.add_no_overlap(intervals)
model.maximize(sum(score * selected[name]
                   for name, score in values))

把程式翻回操作語言

new_bool_var：這個任務要不要做？
interval：任務從哪時開始、持續多久？
optional：可選任務；不是每個請求都必須接受。
add_no_overlap：同一酬載不能同時執行兩個任務。
maximize：優先選擇總價值高的組合。
重點：OR-Tools 不會自動知道「姿態、電量、熱控」；這些必須由任務專家轉成模型規則。

語法對應 CP-SAT scheduling 的 interval、optional interval 與 no-overlap。官方 scheduling recipes

08 / Mission operations architecture

OR-Tools 放在「決策支援層」。

01 · DATA軌道與窗口Skyfield、Orekit 或任務系統產生可見性資料
02 · MODEL候選任務把目標、時長、姿態與資源需求整理成資料
03 · SOLVEOR-Tools在限制條件下選擇與排序任務
04 · VERIFY規則檢查再次驗證電量、記憶體、下傳與命令格式
05 · RELEASE人工核准通過任務規範與值班程序後，才進入命令流程
操作邊界：求解器得到的是「模型下的解」。模型不完整、資料過期或單位／座標錯誤時，最佳解仍可能不是安全解。
09 / How to grow the model

從「排三個任務」逐步長成「任務排程器」

1

時間窗

只能在可見時間內觀測。

2

資源

天線、酬載、電量、記憶體與下傳容量。

3

任務鏈

機動 → 穩定 → 拍攝 → 儲存 → 下傳。

4

不確定性

雲量、延遲、故障與滾動重排。

模型演進順序
可行性→價值最佳化→多資源協同→滾動重排→程序驗證

Google 的 job-shop 範例以 precedence 與 no-overlap 描述任務順序及資源互斥，這正是衛星任務鏈可借用的建模思路。官方案例

10 / Takeaway

把 OR-Tools 記成一句話

您提供任務、資源、限制與價值；它替您搜尋可行且更好的組合。

先從小模型開始

三個任務、一個酬載、一個時間窗，先驗證規則與輸出。

每加一條規則就測試

避免把多個未驗證的操作假設一次塞進模型。

用實際流程包住求解器

資料更新、獨立驗證、人工核准與命令釋出不可省略。
